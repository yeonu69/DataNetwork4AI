HTTP 요청과 응답: 메서드, 상태 코드, 캐시

이렇게 해 보세요
  1. 메서드와 주소를 고르고 [요청 보내기]를 누르면, 브라우저가 실제로 보내는 요청 글자와 서버의 응답 글자가 그대로 나옵니다. HTTP는 사람이 읽을 수 있는 글자로 된 약속입니다.
  2. /old-page(301 이사), /mypage(로그인 쿠키 유무), /admin(403), /nope(404), POST /api/chat(AI 응답)을 차례로 보내 상태 코드를 모아 보세요.
  3. /logo.png를 두 번 보내 보세요. 두 번째는 브라우저 캐시에서 꺼내 요청 자체를 안 보냅니다. [시간 +30초]로 유효 기간을 넘기면 "바뀌었나요?"만 묻고 304를 받습니다.
  4. [서버 과부하]를 켜면 무슨 코드가 오는지 확인합니다.

핵심 3줄
• HTTP 요청은 '메서드 + 주소 + 헤더 + (본문)'입니다. GET은 가져오기, POST는 보내서 처리하기, HEAD는 헤더만 받기입니다.
• 응답의 첫 줄 상태 코드로 결과를 압니다. 2xx 성공, 3xx 다른 곳으로(이사·캐시 그대로), 4xx 요청한 쪽 잘못, 5xx 서버 쪽 문제입니다.
• Cache-Control과 ETag 덕분에 브라우저는 같은 파일을 다시 받지 않습니다. 기한이 지나면 "바뀌었나요?"만 묻고 304로 확인합니다.
