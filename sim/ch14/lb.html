로드밸런싱: AI 요청을 GPU 서버에 나눠 주기

이렇게 해 보세요
  1. 챗봇 질문(요청)이 계속 들어오고, 로드밸런서가 GPU 서버 4대 중 하나를 골라 보냅니다. 요청마다 답의 길이가 달라 처리 시간이 제각각입니다(짧은 답 ●, 긴 답 ⬤). 4번 서버는 구형이라 절반 속도입니다.
  2. 방식을 '라운드 로빈'으로 두고 [시작]을 눌러 대기열과 응답 시간을 봅니다. 차례대로 나눠 주면 느린 서버에 줄이 깁니다.
  3. '가장 한가한 서버'로 바꾸고 [기록 지우기] 후 비교합니다. P99(가장 느린 1%) 응답 시간이 어떻게 달라지나요?
  4. [2번 서버 고장]을 눌러 보세요. 상태 검사(헬스 체크)를 켜고 끄며, 고장 난 서버로 요청이 계속 가는지 확인합니다.
핵심 3줄
• 로드밸런서는 하나의 주소로 들어온 요청을 여러 서버에 나눠, 한 대보다 많은 요청을 처리하고 한 대가 고장 나도 서비스가 계속되게 합니다.
• 라운드 로빈은 단순하지만 요청 크기와 서버 성능이 제각각이면 줄이 한쪽에 몰립니다. AI 추론처럼 처리 시간 차이가 큰 일에는 '가장 한가한 서버' 방식이 꼬리 지연을 크게 줄입니다.
• 헬스 체크로 고장 난 서버를 빨리 빼야 합니다. 빠지기 전까지 그쪽으로 간 요청은 실패합니다.
